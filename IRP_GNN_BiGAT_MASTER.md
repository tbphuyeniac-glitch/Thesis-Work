## 2. Problem statement

This thesis studies a **multi-period Inventory Routing Problem with Lateral Transshipment (IRP-LT)** for a retail distribution setting.

### 2.1 Network structure
- one Central Warehouse (**CW**),
- multiple retail stores,
- multiple products (SKUs),
- multiple time periods,
- optional vehicle routing structure for direct shipments,
- lateral transshipment between stores.

### 2.2 Two-stage operational logic

**Stage 1: Baseline DC-to-store replenishment**
The DC plans and ships products to stores based on forecast demand. This is solved as a full IRPT optimization (ALNS-based or Gurobi-based).

**Stage 2: Post-shock lateral transshipment**
After the baseline plan is executed, actual realized demand is generated by applying a **shocking factor** to the original demand. Because realized demand deviates from forecast:
- Some stores become **shortage stores** (receivers).
- Some stores become **surplus stores** (donors).
- Lateral transshipment (LT) redistributes inventory from donors to receivers to reduce total system cost.

### 2.3 Main computational challenge
The number of possible LT patterns grows very quickly with stores and periods. If all feasible columns are enumerated, the model becomes computationally infeasible.

Therefore, this thesis uses:
- **Column Generation (CG)** to generate promising LT columns,
- **feature-based pruning** to reduce the candidate search space,
- **BiGAT (Bipartite Graph Attention Network)** to score and select the most valuable columns before insertion into the RMP.

## 3. Overall system architecture

The system has five modules.

### M1. Data mapping and validation preparation
File: `irp_gurobi_converted.py` — `DatasetToIRPValidationMapper`

Transforms retail transaction / inventory data into optimization-ready structures:
- stores, SKUs, periods, demand, initial inventory, capacity, cost parameters.
- Supports real Excel/CSV data or synthetic instances.

### M2. Baseline IRPT solver
File: `irp_gurobi_converted.py` — `BaselineALNSModel` (primary), `AchamrahFullIRPTModel` (reference)

- `BaselineALNSModel`: ALNS (Adaptive Large Neighborhood Search) metaheuristic for DC→stores routing without LT. Scalable and Kaggle-friendly.
- `AchamrahFullIRPTModel`: Gurobi MIP baseline (Achamrah 2022 style) — kept for reference and small-instance validation.
- Outputs: baseline inventory trajectories, routing pattern, shortage profile.

### M3. Demand shock mechanism
File: `irp_gurobi_converted.py` — `DemandShockEngine`

After the baseline plan, applies a shocking factor to realized demand:
- `normal`, `gamma`, or `sku_spike` shock distributions.
- Controls: `IRP_DEMAND_SHOCK_PROBABILITY`, `IRP_DEMAND_SHOCK_NON_DISPATCH_MULTIPLIER`, etc.
- Creates post-shock shortage/surplus profile that activates LT.

### M4. LT Column Generation engine
File: `irp_gurobi_converted.py` — `LateralTransshipmentCG`

Builds and solves a restricted master problem using LT patterns:
- RMP with need-cover and surplus-cap constraints,
- dual extraction for pricing,
- feature pruning (4 signals),
- Stackelberg-style acceptance filter,
- iterative re-optimization,
- optional Branch-and-Price (B&P) via `IRP_USE_BRANCH_AND_PRICE=1`.

### M5. BiGAT-guided column ranking
File: `GNN/models/attention/model.py` — `BiGATColumnScorer`

A bipartite graph attention network that:
- takes candidate column nodes (10 features) and RMP constraint nodes (7 features),
- runs 2-layer bidirectional attention,
- outputs a score per column,
- enables top-k selection before RMP insertion.

> **Schema update (E1/E2):** the column feature vector was reduced from 12 → 10
> by dropping `acceptance_score` and `compensation_mean`. Those two features come
> from the Stackelberg compensation game (Section 9), which is disabled in the
> E1/E2 thesis configurations, so they carried no learnable signal and the
> teacher CSV writes them as constants. The data loader slices legacy 12-feature
> pkls down to 10 transparently — no rebuild needed.

### 4.3 High-level current pipeline flow
1. Load dataset (Excel/CSV) → `DatasetToIRPValidationMapper`
2. Build `IRPData` parameters
3. Solve baseline IRPT (ALNS or Gurobi) without LT
4. Apply demand shock → post-shock shortage/surplus profile
5. Generate random warm-start LT patterns
6. Solve LT Restricted Master Problem (RMP)
7. Pricing step: dual-based pair candidates → feature pruning → Stackelberg acceptance → pattern building
8. **[Optional] BiGAT scoring**: build bipartite graph → score patterns → top-k selection
9. Add selected patterns → re-solve RMP until convergence
10. Post-process: LT plan, cost breakdowns, validation comparison

### 4.4 Three-phase operation
- **Phase 1 (offline baseline)**: Run CG in teacher-collection mode, collect training data, build graph dataset, train BiGAT.
- **Phase 2 (online inference)**: Load pre-trained BiGAT checkpoint, use GNN to score columns during CG — no retraining.
- **Phase 3 (online learning)**: Load checkpoint + run CG + fine-tune BiGAT on new teacher rows collected during inference.

Controlled by env vars: `IRP_ONLINE_INFERENCE=1`, `IRP_ONLINE_LEARNING=1`, or `IRP_PHASE_LABEL`.

## 5. Mathematical model

### 5.1 Sets
- `S`: set of stores
- `P`: set of products
- `T`: set of time periods
- `V`: set of vehicles
- `CW`: central warehouse
- `N0 = {CW} ∪ S`

---

### 5.2 Parameters

#### Demand and inventory
- `d_(s,p,t)`: demand of product `p` at store `s` in period `t` (forecast / baseline)
- `d_realized_(s,p,t)`: realized demand after shocking factor is applied
- `I^0_(s,p)`: initial store inventory
- `I^0_(CW,p)`: initial warehouse inventory
- `C_s`: aggregate inventory capacity of store `s`
- `C_CW`: aggregate inventory capacity of warehouse

#### Costs
- `h_(s,p)`: holding cost at store
- `h_(CW,p)`: holding cost at warehouse
- `c^cw_(s,p)`: unit shipment cost from CW to store
- `c^lt_(i,j,p)`: unit LT shipment cost from donor `i` to receiver `j`
- `f^cw_s`: fixed dispatch cost from CW to store `s`
- `f^lt_(i,j)`: fixed dispatch cost for LT pair `(i,j)`
- `π_short_(s,p)`: shortage penalty

#### Routing
- `dist_(i,j)`: routing distance between nodes
- `Qcap`: vehicle capacity
- `Kmax`: maximum vehicles used
- `alpha`: route cost multiplier

#### Warehouse replenishment
- `g_(p,t)`: replenishment into CW for product `p` in period `t`

---

### 5.3 Main decision variables

#### Baseline IRPT variables
- `Qdir_(s,p,t)`: direct shipment from CW to store
- `I_(s,p,t)`: store inventory
- `I_(CW,p,t)`: warehouse inventory
- `B_(s,p,t)`: shortage / unmet demand
- `x_(i,j,v,t) ∈ {0,1}`: arc used by vehicle `v`
- `u_(v,t) ∈ {0,1}`: whether vehicle `v` is used in period `t`
- `z_(i,v,t) ∈ {0,1}`: visit indicator

#### Column generation variables
- `λ_k`: weight of LT pattern / column `k`
- `residual_need_(s,p,t)`: unmet need after selected LT columns cover part of shortage

---

### 5.4 Baseline IRPT objective

\[
\min
\sum_{s,p,t} h_{s,p} I_{s,p,t}
+ \sum_{p,t} h_{CW,p} I_{CW,p,t}
+ \sum_{i,j,v,t} \alpha \, dist_{i,j} x_{i,j,v,t}
+ \sum_{i,j,p,v,t} b_{i,j} y_{i,j,p,v,t}
+ \sum_{s,p,t} \pi^{short}_{s,p} B_{s,p,t}
\]

---

### 5.5 Inventory balance at stores

For each store `s`, product `p`, period `t`:

\[
I_{s,p,t}
=
I_{s,p,t-1}
+ Qdir_{s,p,t}
- d_{s,p,t}
+ B_{s,p,t}
+ \sum_{j \neq s, v} y_{j,s,p,v,t}
- \sum_{j \neq s, v} y_{s,j,p,v,t}
\]

---

### 5.6 Inventory balance at warehouse

\[
I_{CW,p,t}
=
I_{CW,p,t-1}
- \sum_s Qdir_{s,p,t}
+ g_{p,t}
\]

## 6. Demand shock mechanism

### 6.1 Purpose
After the baseline plan is produced, the `DemandShockEngine` generates realized demand by applying a shocking factor.

### 6.2 Shock distributions
Three distribution types are supported:
- `normal`: Gaussian perturbation around baseline demand
- `gamma`: skewed positive perturbation (simulates demand surge)
- `sku_spike`: concentrated spike on a subset of SKUs per period

### 6.3 Control parameters (environment variables)
```
IRP_DEMAND_SHOCK_PROBABILITY             # fraction of store-product-periods shocked
IRP_DEMAND_SHOCK_REALLOCATION_FRACTION   # how much demand is redistributed across stores
IRP_DEMAND_SHOCK_REALLOCATIONS_PER_PRODUCT_PERIOD
IRP_DEMAND_SHOCK_NON_DISPATCH_MULTIPLIER # multiplicative factor on shocked demand
IRP_DEMAND_SHOCK_SEED
```

### 6.4 Output
For each store-product-period:
- `realized_demand = baseline_demand * shock_factor`
- Post-shock shortage = max(0, realized_demand - baseline_inventory_received)
- Post-shock surplus = max(0, baseline_inventory_received - realized_demand)

These shortage/surplus values drive the LT column generation.

## 7. Column generation framework

### 7.1 Why LT is modeled as columns
An LT pattern represents a coherent LT policy for one product-period:
- several donor-receiver arcs,
- quantities assigned to each pair,
- total cost,
- need coverage and donor surplus consumption effects.

### 7.2 LT pattern definition
A pattern `k` contains:
- `pattern_id`, `period`, `product`
- `pattern_flows = {(i,j): qty}`
- `column_cost`
- `metadata` (source, reduced_cost, acceptance_score, etc.)

### 7.3 Restricted Master Problem (RMP)

\[
\min
\text{baseline_without_shortage}
+
\sum_k c_k \lambda_k
+
\sum_{s,p,t} \pi^{short}_{s,p} \, residual\_need_{s,p,t}
\]

#### Need coverage constraints
\[
residual\_need_{s,p,t} + \sum_k a^{need}_{k,s,p,t} \lambda_k \ge need_{s,p,t}
\]

#### Surplus capacity constraints
\[
\sum_k a^{surplus}_{k,s,p,t} \lambda_k \le surplus_{s,p,t}
\]

These generate dual values: `dual_need` and `dual_surplus`, which drive pricing.

### 7.4 Pricing logic
For a donor `i`, receiver `j`, quantity `q`:

\[
rc_{ij} \approx f^{lt}_{ij} + c^{lt}_{ij} q - (dual\_need_j + dual\_surplus_i) q
\]

If `rc < 0`, the pair is promising.

---

## 8. Feature pruning

Before constructing LT patterns, donor-receiver candidate pairs are pruned using four features.

### Feature 1: shortage_ratio
\[
shortage\_ratio = \frac{receiver\_need}{total\_need}
\]
Measures how critical the receiving store is relative to all shortage stores in the same product-period.

### Feature 2: surplus_ratio
\[
surplus\_ratio = \frac{donor\_surplus}{total\_surplus}
\]
Measures how strong the donor is relative to all surplus stores.

### Feature 3: time_urgency
\[
time\_urgency = \frac{1}{1 + days\_until\_stockout}
\]
Measures urgency of the receiving store in time terms.

### Feature 4: negative_reduced_cost
\[
negative\_reduced\_cost = \max(0,\,-\bar{c}(c))
\]
Measures economic attractiveness of the candidate column.

### Feature ranges (default)
```python
feature_ranges = {
    "shortage_ratio":  {"min": 0.40, "max": 1.00},
    "surplus_ratio":   {"min": 0.40, "max": 1.00},
    "distance_band":   {"min": 0.00, "max": 0.75},
    "balance_ratio":   {"min": 0.30, "max": 1.00},
}
```

## 9. Stackelberg-style acceptance layer

> **E1/E2 status:** the Stackelberg layer is part of the design but **disabled**
> in the E1 and E2 thesis configurations. The two derived column features
> `acceptance_score` and `compensation_mean` therefore carry no signal in those
> regimes and have been dropped from the GNN input (Section 10.2). Re-enabling
> Stackelberg in a future configuration would require restoring the 12-feature
> schema or adding the two features back as additional inputs.

For each donor-receiver pair that passes feature pruning, a Stackelberg game decides acceptance:

**Donor side**: worries about shortage risk increase, shipping burden, service-level loss.
**Receiver side**: values shortage reduction, service gain, minus handling and compensation.

For each pair, the code computes: compensation, donor utility, receiver utility, acceptance score, accept/reject.

Only accepted pairs are passed to pattern building.

## 10. BiGAT design

### 10.1 Role in the pipeline
BiGAT is inserted **after patterns are built** and **before they are added to the RMP**. It ranks candidate patterns by their context-aware admission priority. GNN does NOT replace optimization — it improves search efficiency by selecting the most promising columns.

### 10.2 Inputs to BiGAT

**A. Candidate LT column nodes**
Each candidate column is represented by 10 features (defined in `GNN/utilities.py`):

```python
COLUMN_FEATURE_NAMES = [
    "reduced_cost",           # negative reduced cost (economic attractiveness)
    "total_flow",             # total quantity moved in this column
    "n_pairs",                # number of donor-receiver pairs
    "total_need_covered",     # total shortage coverage
    "total_surplus_consumed", # total donor surplus consumed
    "avg_shortage_ratio",     # avg weighted shortage_ratio across pairs
    "avg_surplus_ratio",      # avg weighted surplus_ratio across pairs
    "avg_time_urgency",       # avg weighted time_urgency across pairs
    "avg_negative_reduced_cost",  # avg pair-level negative reduced cost
    "column_cost",            # total pattern cost
]

# Legacy 12-feature pkls also stored "acceptance_score" and "compensation_mean"
# at indices 9 and 10. Those features are products of the Stackelberg layer,
# which is inactive in E1/E2; `utilities.graph_to_tensors` slices them out at
# load time so legacy pkls are usable without rebuilding the dataset.
_LEGACY_COLUMN_FEATURE_INDICES_TO_DROP = (9, 10)
```

**B. RMP constraint nodes**
Each active RMP constraint is represented by 7 features:

```python
CONSTRAINT_FEATURE_NAMES = [
    "dual_value",             # current LP dual value
    "raw_rhs_amount",         # RHS amount (need or surplus)
    "covered_amount",         # how much is already covered by current λ
    "residual_slack",         # remaining uncovered amount
    "urgency_or_scarcity",    # normalized urgency (need) or scarcity (surplus)
    "is_need_constraint",     # 1.0 if this is a need-cover constraint
    "is_surplus_constraint",  # 1.0 if this is a surplus-cap constraint
]
```

**C. Edges**
Each edge (column k → constraint c) has 3 features:

```python
EDGE_FEATURE_NAMES = [
    "quantity",                       # flow quantity relevant to this constraint
    "fraction_covered_or_consumed",   # fraction of need covered or surplus consumed
    "dual_times_quantity",            # dual_value * quantity (economic weight)
]
```

### 10.3 Bipartite graph structure

**Left side: Column nodes** — one node per candidate LT pattern.
**Right side: Constraint nodes** — one node per active RMP constraint (need-cover or surplus-cap).
**Edge**: column k → constraint c if column k affects constraint c.

An edge exists when:
- Column sends flow to a receiver involved in a need-cover constraint, OR
- Column draws from a donor involved in a surplus-cap constraint.

### 10.4 Message passing (2 layers, bidirectional)

**Layer 1:**
```
h_con = LayerNorm(h_con + BipartiteAttentionLayer(col→con)(h_col, h_con, edges, edge_attr))
h_col = LayerNorm(h_col + BipartiteAttentionLayer(con→col)(h_con, h_col, edges_rev, edge_attr))
```

**Layer 2:**
```
h_con = LayerNorm(h_con + BipartiteAttentionLayer(col→con)(h_col, h_con, edges, edge_attr))
h_col = LayerNorm(h_col + BipartiteAttentionLayer(con→col)(h_con, h_col, edges_rev, edge_attr))
```

Each `BipartiteAttentionLayer` computes:
1. Project source, destination, and edge features.
2. Compute attention scores: `e = LeakyReLU(a^T [W_src h_src || W_dst h_dst || W_e g_e])`.
3. Normalize with softmax over neighbors.
4. Aggregate: weighted sum of source messages + edge features.
5. Output: `Linear([h_dst || aggregated])` with ReLU + Dropout.

Note: The graph uses only column→constraint edges. The reverse (constraint→column) pass reuses the same edges with swapped indices. So the model only needs `edge_index_col_to_con` and `edge_attr_col_to_con`.

### 10.5 Scoring head

```python
scoring_head = nn.Sequential(
    nn.Linear(hidden_dim, hidden_dim),
    nn.ReLU(),
    nn.Dropout(dropout),
    nn.Linear(hidden_dim, 1),
)
score_k = scoring_head(h_col_final)
```

The score is interpreted as **admission priority** (higher = more likely to be inserted).

### 10.6 Top-k selection
1. All candidate columns receive a score.
2. Columns are sorted in descending order.
3. Only the top-k columns are inserted into the RMP.

`k` is controlled by `IRP_HEURISTIC_TOP_K` env var.

## 11. Actual BiGAT implementation

### 11.1 Model class (`GNN/models/attention/model.py`)

```python
class BipartiteAttentionLayer(nn.Module):
    def __init__(self, hidden_dim: int, edge_dim: int, dropout: float = 0.0):
        self.src_proj = nn.Linear(hidden_dim, hidden_dim, bias=False)
        self.dst_proj = nn.Linear(hidden_dim, hidden_dim, bias=False)
        self.edge_proj = nn.Linear(edge_dim, hidden_dim, bias=False)
        self.attn = nn.Linear(3 * hidden_dim, 1, bias=False)
        self.out = nn.Sequential(nn.Linear(2 * hidden_dim, hidden_dim), nn.ReLU(), nn.Dropout(dropout))

    def forward(self, src_x, dst_x, edge_index, edge_attr) -> torch.Tensor:
        # edge_index: [2, E], edge_index[0]=src, edge_index[1]=dst
        src_h = self.src_proj(src_x)
        dst_h = self.dst_proj(dst_x)
        edge_h = self.edge_proj(edge_attr)
        raw = self.attn(torch.cat([src_h[src_idx], dst_h[dst_idx], edge_h], dim=-1)).squeeze(-1)
        raw = F.leaky_relu(raw, negative_slope=0.2)
        # Per-destination softmax aggregation
        aggregated = weighted_sum_per_destination(raw, src_h + edge_h, dst_idx)
        return self.out(torch.cat([dst_x, aggregated], dim=-1))


class BiGATColumnScorer(nn.Module):
    def __init__(self, column_dim=10, constraint_dim=7, edge_dim=3, hidden_dim=64, dropout=0.1):
        # Encoders with LayerNorm
        self.column_encoder = Sequential(Linear(column_dim, hidden_dim), ReLU(), Dropout, Linear)
        self.constraint_encoder = Sequential(...)
        self.column_norm0, self.constraint_norm0 = LayerNorm, LayerNorm
        # 2 attention layers each direction
        self.col_to_con_1, self.con_to_col_1 = BipartiteAttentionLayer(...)
        self.col_to_con_2, self.con_to_col_2 = BipartiteAttentionLayer(...)
        # Layer norms after each pass
        self.column_norm1, self.constraint_norm1, self.column_norm2, self.constraint_norm2
        # Scoring head
        self.scoring_head = Sequential(Linear(hidden_dim, hidden_dim), ReLU, Dropout, Linear(hidden_dim, 1))

    def encode_graph(self, column_features, constraint_features, edge_index_col_to_con, edge_attr_col_to_con):
        h_col = column_norm0(column_encoder(column_features))
        h_con = constraint_norm0(constraint_encoder(constraint_features))
        # Reverse edges for con→col pass
        edge_index_con_to_col = flip(edge_index_col_to_con)
        # Layer 1 (residual connections)
        h_con = constraint_norm1(h_con + col_to_con_1(h_col, h_con, edges_col_to_con, attrs))
        h_col = column_norm1(h_col + con_to_col_1(h_con, h_col, edges_con_to_col, attrs))
        # Layer 2 (residual connections)
        h_con = constraint_norm2(h_con + col_to_con_2(h_col, h_con, edges_col_to_con, attrs))
        h_col = column_norm2(h_col + con_to_col_2(h_con, h_col, edges_con_to_col, attrs))
        return h_col, h_con

    def forward(self, column_features, constraint_features, edge_index_col_to_con, edge_attr_col_to_con):
        h_col, _ = self.encode_graph(...)
        return self.scoring_head(h_col).squeeze(-1)
```

## 12. Teacher data collection and GNN training pipeline

### 12.1 What is teacher data?
During CG with `IRP_COLLECT_TEACHER_MODE=1`, at each pricing iteration, the pipeline records:
- The current bipartite graph state (column features, constraint features, edge features).
- Labels for each candidate column: `1` if the column was eventually selected into the optimal CG solution, `0` otherwise.

This creates supervised training data: graph state + column labels per CG iteration.

### 12.2 Teacher data schema (CSV columns)
Each row in `cg_teacher_dataset.csv` corresponds to one candidate LT column at one CG iteration:
```
source_instance, branch_node_id, episode, product, period,
pattern_id, column_cost, reduced_cost, total_flow, n_pairs,
total_need_covered, total_surplus_consumed, avg_shortage_ratio,
avg_surplus_ratio, avg_time_urgency, avg_negative_reduced_cost,
acceptance_score, compensation_mean,           # written but dropped by builder
constraint_features_json,  # JSON array of constraint feature vectors
constraint_state_hash,     # SHA-1 of constraint_features_json (for grouping)
edge_features_json,        # JSON array of edge feature vectors
edge_index_json,           # JSON array of [col_idx, con_idx] pairs
label                      # 1 if selected, 0 otherwise
```

> `acceptance_score` and `compensation_mean` are still written by the teacher
> exporter for backwards compatibility, but `build_teacher_graph_dataset.py`
> drops them when materializing the per-sample pkl. Downstream training and
> inference both consume the 10-feature schema only.

Each `.pkl` file is a dict with keys (one (product, period) group per sample):

detects them and slices indices 9–10 on load.

#### 12.4.1 Ranking filter (Fix A)
Pass `--ranking-filter-groups` to drop signal-less groups before training:

| Rule | Reason |
|---|---|
| `size < min-group-size` (default 2) | no pairwise comparison possible |
| all-positive group | softplus pairwise loss is identically zero |
| all-negative group | softplus pairwise loss is identically zero |
| `size > max-group-size` (default 64) | stratified-cap to preserve positive ratio |

Example yields on the E2 teacher CSV: 21,861 size<2 + 9,381 all-positive + 160
zero-positive groups dropped, leaving 14,880 mixed-label groups (9,300 train /
3,002 valid / 2,578 test).

#### 12.4.2 Constraint feature propagation
The teacher exporter de-duplicates `constraint_features_json` to the first row
of each export batch (one (source_instance, branch_node_id, episode,
constraint_state_hash) bundle). `propagate_constraint_features_json()` fans the
JSON back across all (product, period) groups in the same batch *before*
grouping. An earlier bug propagated by the full group key, which silently
zero-padded ~99% of constraint matrices on E1 — that has been fixed.
`dataset_summary.json` now records `groups_repaired_zero_padded` per split;
both filtered datasets currently report 0 repaired groups.

### 12.5 BiGAT training
File: `GNN/03_train_bigat.py`

```bash
python GNN/03_train_bigat.py \
    --data-dir GNN/data/irplt_teacher_E2_filtered \
    --out-dir GNN/trained_models/irplt_teacher_E2_filtered/bigat/pairwise_rank \
    --objective pairwise_rank \
    --epochs 50 \
    --lr 1e-3 \
    --hidden-dim 64 \
    --dropout 0.1 \
    --patience 15
```

Defaults (after the cleanup): `--epochs 50`, `--hidden-dim 64`, `--patience 15`.
The earlier defaults (5 / 16 / 8) were too small — the model under-fit and the
validation `score_gap` plateaued near 0.1.

Training objectives:
- `pairwise_rank` (PRIMARY): pairwise ranking loss within each sample group.
  Each pkl already represents one (product, period) group with K columns, so
  the within-sample softplus loss IS the within-group pairwise loss.
- `score_regression`: smooth-L1 against the teacher score.
- `binary`: binary cross-entropy with positive-weight rebalancing.

Early stopping: highest `ranking_mrr` on valid (pairwise_rank), else lowest
validation loss.

Recommended sanity checks during training:
- `score_gap > 0.2` by epoch 10 — if it plateaus near 0.1, suspect zeroed
  constraint features (`groups_repaired_zero_padded` > 10% in summary) or a
  too-small `hidden_dim`.
- `ranking_top3_hit ≈ 1.0` is uninformative on this dataset because most
  groups have K ≤ 3; rely on `ranking_mrr` and `mean_positive_rank` instead.

### 12.6 Dantzig vs GNN ranking comparison
File: `GNN/eval_dantzig_vs_gnn.py`

```bash
python GNN/eval_dantzig_vs_gnn.py \
    --data-dir GNN/data/irplt_teacher_E2_filtered \
    --split test \
    --checkpoint GNN/trained_models/irplt_teacher_E2_filtered/bigat/pairwise_rank/best_model.pt \
    --hard-rho-threshold 0.3 \
    --out-file Results/eval_dantzig_vs_gnn.json
```

For each (product, period) test group:
- **Dantzig MRR**: rank columns by `reduced_cost` ascending, MRR = 1 / rank of best positive.
- **GNN MRR**: rank columns by BiGAT logits descending, MRR = 1 / rank of best positive.
- **Spearman(-RC, label)**: within-group correlation. Hard groups have ρ ≤ 0.3.

Reference Dantzig numbers on the E2 test split (no GNN): full = 0.8088, hard
(52.9%) = 0.6877, easy (47.1%) = 0.9449. The thesis claim that GNN beats
Dantzig requires `gnn_mrr > 0.8088` overall and (more importantly)
`gnn_mrr > 0.6877` on hard groups.

## 13. Exact integration into the current code (`irp_gurobi_converted.py`)

### 13.1 Current pricing workflow with GNN
The integration point is inside `LateralTransshipmentCG._candidate_patterns_from_duals()` or the wrapper `pricing_step()`:

```python
def pricing_step(self, master_solution, rc_tol=-1e-6):
    need, surplus = self._build_need_and_surplus_proxies()

    # Step 1: build raw candidate patterns from duals + pruning + Stackelberg
    raw_patterns = self._candidate_patterns_from_duals(
        need=need, surplus=surplus,
        active_product_periods=master_solution.active_product_periods,
        dual_need=master_solution.dual_need,
        dual_surplus=master_solution.dual_surplus,
        rc_tol=rc_tol,
    )

    if self.gnn_model is not None and raw_patterns:
        # Step 2: build bipartite graph
        graph_data = self.build_bigraph_for_patterns(
            patterns=raw_patterns,
            need=need, surplus=surplus,
            dual_need=master_solution.dual_need,
            dual_surplus=master_solution.dual_surplus,
        )
        # Step 3: GNN scoring
        scores = score_graph(self.gnn_model, graph_data)
        # Step 4: top-k selection
        raw_patterns = self.select_top_k_patterns(raw_patterns, scores, k=self.top_k_columns)

    return raw_patterns
```

### 13.2 Three-way benchmark runner
File: `irp_gurobi_converted.py` — `run_three_way_benchmark()`

Controlled by `IRP_RUN_BENCHMARK=1`. Runs three variants on the same instance:
- **Classical CG**: feature pruning + Stackelberg, no GNN (add ALL negative-rc columns).
- **Heuristic CG**: feature pruning + Stackelberg + top-k heuristic (no GNN, rule-based top-k).
- **GNN CG**: feature pruning + Stackelberg + BiGAT scoring → top-k.

Outputs: `Results/benchmark/irp_benchmark_comparison.csv` with side-by-side costs and runtimes.

## 15. Training strategy for BiGAT

### 15.1 Offline supervised training (primary)
1. Run the CG process on many historical or synthetic instances (`generate_teacher_scenarios.py`).
2. At each CG iteration, collect candidate columns and the graph state.
3. Label columns: `1` if eventually selected into RMP and contributed positively, `0` otherwise.
4. Build graph PKL samples (`build_teacher_graph_dataset.py`).
5. Train BiGAT with pairwise ranking loss (`03_train_bigat.py`).

### 15.2 Loss functions
For pairwise ranking (PRIMARY):
```python
# For each (pos, neg) pair: margin loss
loss = sum(max(0, margin - (score_pos - score_neg))) / n_pairs
# or soft version:
loss = sum(log(1 + exp(score_neg - score_pos))) / n_pairs
```

For binary classification (alternative):
\[
\mathcal{L} = BCE(score_k, y_k)
\]

### 15.3 Online inference (Phase 2)
During CG:
1. Build graph from current candidates and current RMP state.
2. Load pre-trained BiGAT (`IRP_GNN_CHECKPOINT`).
3. Run forward pass → scores.
4. Keep top-k columns → insert into RMP.

### 15.4 Online learning (Phase 3)
As Phase 2, plus:
- Collect new teacher rows from the inference CG episode.
- After each inference run, fine-tune the checkpoint in-place (`resume_checkpoint=True`).
- Use `IRP_ONLINE_LEARNING_EPOCHS=2` (small to avoid overfitting to a single run).

## 16. What BiGAT learns

BiGAT is NOT learning vehicle routes or replacing optimization.
It learns **admission priority of LT columns**, specifically:

1. **Structural importance**: which columns connect to the most critical need constraints and scarcest surplus constraints.
2. **Context-aware usefulness**: a column useful in isolation may not be good given current duals, slack, shortage profile, and donor scarcity.
3. **Competitive interaction**: columns may compete for same donor surplus or overlap covering same shortage; the graph models this via shared constraint neighbors.
4. **Economic-operational tradeoff**: implicitly balances reduced cost, flow magnitude, shortage coverage, scarcity burden, acceptance score.
5. **Better ranking than pure heuristics**: learns from solved instances which column patterns are usually worth admitting.

## 17. Full thesis algorithm

### Phase A. Data preparation
1. Load retail data (Excel/CSV) → `DatasetToIRPValidationMapper`
2. Build `IRPData` (demand, inventory, capacity, costs, distances)
3. Build validation target

### Phase B. Baseline optimization
4. Solve `BaselineALNSModel` (ALNS, no LT)
5. Extract baseline inventory trajectories and shortage profile

### Phase C. Demand shock
6. Apply shocking factor to realized demand
7. Compute post-shock shortage and surplus per store-product-period
8. Identify active (product, period) pairs for LT

### Phase D. LT candidate generation (CG pricing)
9. Build need and surplus proxies from post-shock state
10. Identify active product-periods
11. Generate donor-receiver pair candidates
12. Compute feature values (shortage_ratio, surplus_ratio, time_urgency, negative_reduced_cost)
13. Apply feature pruning (filter by feature_ranges)
14. Apply Stackelberg acceptance filter
15. Build LT pattern candidates

### Phase E. BiGAT-guided selection
16. Build bipartite graph:
   - Column nodes: 10-feature vectors
   - Constraint nodes: 7-feature vectors (need-cover + surplus-cap)
   - Edges: 3-feature vectors
17. Run BiGAT encode_graph → scoring_head
18. Select top-k columns

### Phase F. Master problem update
19. Add selected columns to RMP
20. Re-solve RMP (Gurobi LP relaxation)
21. Extract updated dual values

### Phase G. Loop
22. Repeat D–F until no improving columns or convergence

### Phase H. Output
23. Post-process LT plan, cost breakdowns, validation comparison
24. (Optional) Run 3-way benchmark

## 19. Thesis contribution statement

1. A practical IRPT framework with lateral transshipment for retail distribution.
2. A demand shock mechanism that creates realistic post-plan inventory imbalance.
3. A column generation mechanism that avoids full enumeration of LT policies.
4. A feature-driven candidate pruning layer (4 signals) to control search complexity.
5. A Stackelberg acceptance filter that models practical donor-receiver negotiation.
6. A BiGAT module that ranks LT columns by learning column-constraint interactions in the current RMP state.
7. A hybrid optimization-learning architecture where mathematical programming preserves feasibility and GNN improves search efficiency.
8. A three-phase deployment framework (offline training → online inference → online learning).
9. A three-way benchmark (Classical vs Heuristic vs GNN) for systematic comparison.

### 21.3 Key integration rules
- Never use torch_geometric — the model uses pure PyTorch only.
- Edge_index is always `[2, n_edges]` with `[0]=src (col)`, `[1]=dst (con)`.
- Reverse for con→col pass: `torch.stack([edge_index[1], edge_index[0]], dim=0)`.

- Teacher labels are floats (0.0 / 1.0), but `labels_binary` is also stored.
- All feature tensors use `.float()` — apply before passing to model.
